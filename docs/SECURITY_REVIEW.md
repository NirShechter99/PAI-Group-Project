## טיפול באישורים ובטוקנים

- הסיסמה מוזנת בטופס ההתחברות ומושווית ל־bcrypt hash. JWT כולל מזהה משתמש וגרסת טוקן, ונחתם במפתח מהסביבה. תוקפו 24 שעות.
- JWT נשמר ב־cookie מסוג HttpOnly ו־SameSite=Strict. ב־NODE_ENV=production ה־cookie גם Secure ולכן נדרש HTTPS. הוא אינו נשמר ב־localStorage.
- logout מגדיל את tokenVersion במסד ומוחק את ה־cookie, כך שגם עותק ישן של הטוקן אינו ממשיך להיות תקף. שינוי פרטי חשבון דרך ה־API מבטל טוקנים קודמים.
- פעולות משנות נתונים מחייבות CSRF token תואם ל־cookie חתום; גם העלאת תמונה מוגנת. קיימת הגבלת ניסיונות התחברות הנשמרת במסד.
- בדיקות נוספות כוללות escaping של HTML ומטא־דאטה, חסימת קלט שאינו תקין, מניעת חשיפת כתבה לפני אישור, והפרדת טיוטה מהגרסה הציבורית.

## תנאים בהרצה ובהגשה

יש לשמור את `.env` מקומית בלבד, לבחור JWT_SECRET אקראי וסיסמת הדגמה פרטית, ולשמור על אותו מסד ומפתח בבדיקת Restart. תפוגה רגילה לאחר 24 שעות או logout מכוונים אינם כשל ב־Restart. שינוי המפתח מבטל התחברויות קיימות.

בקבצי המקור הנוכחיים אין מפתח ברירת מחדל או יצירה אוטומטית של חשבונות עם סיסמה חלשה. סודות שהופיעו בגרסאות קודמות עדיין נמצאים בהיסטוריית Git; בעלי החשבונות חייבים לבטל/להחליף אותם. לא בוצעה החלפה שלהם במסגרת הבדיקות ולא שוכתבה ההיסטוריה.

הבדיקות משתמשות במסד זמני ונפרד. יש להריץ `npm run preflight` על מחשב ההצגה עם מסד ההדגמה בפועל. תוצאות כלל הבדיקות מופיעות ב־[VERIFICATION.md](VERIFICATION.md).
